Self-hosted voice integration

Saylo runs the call. Your app decides what to say.

Run Saylo on your infrastructure and connect your application endpoint. Saylo handles the voice; your app supplies the answers and actions.

  1. 01 · Caller

    Browser or phone

    WebRTC (WHIP) from a browser, Twilio Media Streams for phone calls, or any SIP trunk through sip-server.

  2. 02 · Saylo server :8080

    Hears and takes turns

    Speech detection, turn-taking, barge-in, echo guard, and speech-to-text that adapts to the caller.

  3. 03 · Your agent

    Decides what to say

    Saylo posts each turn to one HTTP endpoint of yours, with its language. You reply with text.

  4. 04 · Voice router :8300

    Speaks it

    Sentence by sentence: Kokoro on the GPU in ~130ms a sentence, Sarvam for Indian languages.

Integrate with your app

Your app. A voice.

Run the voice runtime, connect your endpoint, and return what to say. You bring your provider accounts and application logic.

Self-hosted setup guide Try the browser demo
1

Run Saylo

Add your speech-provider keys and start the server and voice router. The default Docker setup uses Linux and an NVIDIA GPU. See requirements.

cp .env.example .env
# Add your provider keys locally.
docker compose up --build
2

Connect your application

Set your endpoint in the runtime config. Saylo sends each conversation event to your app; the shared key authenticates those requests.

[agent]
url = "https://your-app.example.com/voice/agent"
# Set STREAMCORE_AGENT_API_KEY on both sides.
3

Reply with what to say

Handle the four event types: listen, greeting, chat, and oneshot. Your app returns text; Saylo speaks it to the caller.

Return a reply such as {"text":"[lang:en] How can I help?"}. See the request contract and example application →
